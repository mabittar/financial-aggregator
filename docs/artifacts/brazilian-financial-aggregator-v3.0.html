Overview

Plataforma multi-usuário para acompanhamento e agregação de investimentos brasileiros e globais. Autenticação baseada em JWT (HMAC-SHA256 via golang-jwt/jwt/v5), com gerenciamento completo de ciclo de vida de usuários no ledger-core (registro, atualização, deleção e autenticação). As rotas não possuem identificador do usuário no path, pois o contexto do usuário é extraído diretamente das claims do token JWT (user_id, username, role).

O S3 (Ingest + Parser do JSON canônico) é realizado diretamente no ledger-core em Golang (go-chi/chi v5), mantendo o controle centralizado das posições e staging de extratos no Go. O Worker Python é acionado na etapa S6 (Market Data & Analytics), onde todos os seus inputs, outputs, domínios e Objetos de Valor (Value Objects - DDD) são rigorosamente validados utilizando Pydantic @latest (v2).

💡 Definições de Responsabilidade v3.0:
  • Multi-user com JWT Embedded Context: Rotas limpas sem {user} no path. O user_id é extraído do token JWT pelo middleware de autenticação Chi.
  • Ledger Core em Go com go-chi/chi (v5): Gerencia Auth, CRUD de Usuários, Portfólios, Holdings e o Ingest + Parser do JSON canônico (S3).
  • Worker Python focado em Market Data & Analytics (S6): O Worker é acionado a partir de Market Data / XIRR / Monte Carlo. Todos os inputs, outputs, entidades de domínio e Objetos de Valor (DDD VOs) do Worker Python possuem schema validator estrito via Pydantic @latest (v2).
  • Database Migrations Padronizadas: Migrações declarativas via golang-migrate/migrate no core Go e suporte ao Alembic / golang-migrate no Worker Python.

Auth & User Management (JWT) MULTI-USER

Arquitetura de autenticação centralizada no ledger-core em Golang. Todas as rotas autenticadas exigem o cabeçalho Authorization: Bearer <token> (ou cookie httpOnly). O middleware Chi valida a assinatura HS256 e injeta o objeto CustomClaims no contexto da requisição (r.Context()).

Modelo de Claims JWT (Golang `golang-jwt/jwt/v5`)

type CustomClaims struct {
	UserID   string `json:"user_id"`
	Username string `json:"username"`
	Role     string `json:"role"`
	jwt.RegisteredClaims
}

O UserID é a chave primária UUID do usuário, garantindo o isolamento multi-tenant nas consultas SQL (WHERE user_id = $1) e nas políticas de RLS no PostgreSQL.

🔑 Operações de Usuário no Backend (Go Ledger)

  • Registro (POST /api/v1/auth/register): Cria usuário na tabela users com hash de senha seguro (bcrypt cost 12).
  • Login (POST /api/v1/auth/login): Valida credenciais e emite o token JWT com expiração de 15 minutos.
  • Perfil (GET /api/v1/users/me): Retorna os dados do usuário autenticado a partir das claims do token.
  • Atualização (PUT /api/v1/users/me): Permite atualizar nome de usuário, e-mail e alterar senha.
  • Deleção (DELETE /api/v1/users/me): Remove a conta do usuário e realiza expurgo em cascata de seus portfólios, holdings e históricos.

💻 Integração com Frontend (Next.js 16.3)

  • Formulários de Login & Registro: Páginas dedicadas /login e /register com validação no cliente.
  • Armazenamento Seguro: JWT mantido em estado / httpOnly Cookie ou storage seguro com auto-anexação no fetch client-side.
  • Gerenciamento de Conta: Painel do usuário /settings/profile para atualizar informações e deletar a conta.
  • Route Guards: Middleware Next.js protegendo rotas privadas e redirecionando não-autenticados para /login.

no JSON canônico (schema assets/movements). Regras:
1. Linhas em NEGRITO são SUBTOTAIS de grupo -> vão em "subtotals", nunca "assets".
2. "—" ou vazio -> null. Números BR (1.234,56) e US (1,234.56) -> float puro.
3. Prefixo R$ -> currency BRL; prefixo $ -> USD. Registre em "currency".
4. asset_class por regex do nome:
   LCA|LCD->lca/lcd ; CDB->cdb ; DEB->debenture ; NTN-B|Tesouro->tesouro ;
   ticker XXXX[0-9]$ ->acao ; XXXX11$ ->fii ; ETF/ADR US ->etf/bdr ;
   "FIC|FIM|FIA|Prev"->fundo ; senão ->outro.
5. position_model: "quantity" p/ ação|fii|etf|bdr ; "value" p/ renda fixa,
   Tesouro, debênture, fundos e qualquer coisa sem preço unitário confiável.
6. movements.type: COMPRA->buy ; VENDA->sell ; RENDIMENTOS|dividendos->dividend ;
   JUROS S/CAPITAL->jscp ; REPASSE JUROS|Tesouro juros->interest ;

   Resgate->withdrawal ; Taxa|emolumento|OPERAÇÕES EM BOLSA->fee.
7. amount MANTÉM o sinal do extrato (negativo=saída, positivo=entrada).

Regras de Consolidação (ativo pré-existente, novo ativo, Tesouro sem cotas)

Distinção central mantida: quantity-based vs value-based. Todo o isolamento é mantido no escopo do usuário autenticado.

📦 quantity-based ações · FIIs · ETFs · BDRs

Match por ticker_or_code e user_id. Posição = quantidade × preço.

  • Novo ativo: cria holding para o usuário + 1ª transaction buy.
  • Já existe + nova compra: adiciona transaction ao holding do usuário e recalcula preço médio ponderado.
novo_avg = (qtd_ant*avg_ant + qtd_nova*preço_nova)
           / (qtd_ant + qtd_nova)

💰 value-based CDB · LCA/LCD · Tesouro · deb · fundos

Sem cotas discretas confiáveis. Valor financeiro é a fonte da verdade; quantity é informativo.

  • Novo ativo: match por normalize(name) + portfolio_name + user_id → cria holding.
  • Já existe + novo aporte: adiciona transaction; posição vem do gross_value do statement.
  • Valorização mensal: vem do gross_value e month_return_pct informados no extrato.

Spec: JWT Authentication & User CRUD

Especificação detalhada do ciclo de vida de tokens JWT e das operações de gerenciamento de usuários no ledger-core.

package main

import (
	"errors"
	"fmt"
	"time"

	"github.com/golang-jwt/jwt/v5"
)

// Define a secret key (Keep this in environment variables in production!)
var jwtSecret = []byte("your-highly-secure-secret-key")

// CustomClaims defines the structure of your payload data
type CustomClaims struct {
	UserID   string `json:"user_id"`
	Username string `json:"username"`
	Role     string `json:"role"`
	jwt.RegisteredClaims
}

// GenerateToken creates a signed JWT string valid for 15 minutes
func GenerateToken(userID, username, role string) (string, error) {
	claims := CustomClaims{
		UserID:   userID,
		Username: username,
		Role:     role,
		RegisteredClaims: jwt.RegisteredClaims{
			ExpiresAt: jwt.NewNumericDate(time.Now().Add(15 * time.Minute)),
			IssuedAt:  jwt.NewNumericDate(time.Now()),
			NotBefore: jwt.NewNumericDate(time.Now()),
			Issuer:    "braff-ledger-core",
		},
	}

	// Create token with HS256 algorithm and claims
	token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)

	// Sign the token with our secret
	return token.SignedString(jwtSecret)
}

// VerifyToken parses, validates the signature, and extracts claims from a token string
func VerifyToken(tokenString string) (*CustomClaims, error) {
	// Parse the token using our custom claims structure
	token, err := jwt.ParseWithClaims(tokenString, &CustomClaims{}, func(t *jwt.Token) (interface{}, error) {
		// Crucial security step: Always validate the signing method before returning the key
		if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
			return nil, fmt.Errorf("unexpected signing method: %v", t.Header["alg"])
		}
		return jwtSecret, nil
	})

	if err != nil {
		return nil, err
	}

	// Extract and validate the claims
	if claims, ok := token.Claims.(*CustomClaims); ok && token.Valid {
		return claims, nil
	}

	return nil, errors.New("invalid token claims")
}
  • Login: O usuário envia credenciais em POST /api/v1/auth/login. A senha é verificada contra o hash armazenado no PostgreSQL (bcrypt).
  • Emissão de Token: O servidor emite um JWT de acesso (15 min) contendo user_id, username e role. Opcionalmente emite um Refresh Token em cookie HTTP-Only.
  • Injeção de Contexto: O Middleware Chi extrai o token do header Authorization: Bearer <token>, valida a assinatura HMAC-SHA256 via VerifyToken e insere os claims no r.Context().
  • Execução de Request: Os handlers acessam claims.UserID do contexto para executar queries SQL estritamente filtradas pelo ID do usuário.

Spec: Go Ledger Core (go-chi/chi v5)

O ledger-core é estruturado com o roteador go-chi/chi (v5), gerenciando Usuários, Auth, Portfólios, Holdings e a recepção e parsing do Input Mensal de Extratos (S3 Ingest).

package main

import (
	"net/http"
	"github.com/go-chi/chi/v5"
	"github.com/go-chi/chi/v5/middleware"
)

func SetupRouter() *chi.Mux {
	r := chi.NewRouter()

	r.Use(middleware.Logger)
	r.Use(middleware.Recoverer)
	r.Use(middleware.RealIP)

	// Rotas Públicas (Auth)
	r.Route("/api/v1/auth", func(r chi.Router) {
		r.Post("/register", RegisterHandler)
		r.Post("/login", LoginHandler)
	})

	// Rotas Protegidas por JWT
	r.Group(func(r chi.Router) {
		r.Use(JWTAuthMiddleware)

		// Gerenciamento de Usuário
		r.Route("/api/v1/users", func(r chi.Router) {
			r.Get("/me", GetProfileHandler)
			r.Put("/me", UpdateProfileHandler)
			r.Delete("/me", DeleteUserHandler)
		})

		// Portfólios, Statements (S3 Ingest) e Reconciliação (S4)
		r.Route("/api/v1/portfolios", func(r chi.Router) {
			r.Get("/", ListPortfoliosHandler)
			r.Post("/", CreatePortfolioHandler)
			r.Post("/{portfolio_name}/{YYYYMMDD}/assets", PostAssetsIngestHandler)
			r.Post("/{portfolio_name}/{YYYYMMDD}/mov", PostMovementsIngestHandler)
			r.Get("/{portfolio_name}/{YYYYMMDD}/reconciliation", GetReconciliationHandler)
			r.Post("/{portfolio_name}/{YYYYMMDD}/confirm", ConfirmReconciliationHandler)
		})

		r.Route("/api/v1/holdings", func(r chi.Router) {
			r.Get("/", ListHoldingsHandler)
			r.Get("/{id}/transactions", ListTransactionsHandler)
		})
	})

	return r
}

Spec: Worker Python (Pydantic @latest & Market Data)

O worker Python é acionado a partir da etapa S6 (Market Data & Analytics). Todas as suas rotas, inputs, outputs, entidades de domínio e Objetos de Valor da Arquitetura Orientada a Domínio (DDD Value Objects) utilizam Pydantic v2 (versão mais recente) com modelos imutáveis e validação estrita.

from pydantic import BaseModel, Field, ConfigDict, field_validator
from typing import Optional, List
from datetime import datetime
from enum import Enum

class BenchmarkType(str, Enum):
    SELIC = "SELIC"
    PTAX = "PTAX"
    IBOV = "IBOV"
    IFIX = "IFIX"
    SP500 = "SP500"
    NASDAQ = "NASDAQ"
    FEDFUNDS = "FEDFUNDS"

# Value Object (DDD) Imutável para Cotações e Benchmarks
class QuotePointVO(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    symbol: str = Field(min_length=1)
    timestamp: datetime
    price: float = Field(gt=0)
    currency: str = Field(default="BRL", pattern="^[A-Z]{3}$")

# Value Object (DDD) Imutável para Requisição de Market Data
class MarketDataQueryVO(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    benchmark: BenchmarkType
    start_date: str = Field(pattern="^\\d{8}$")
    end_date: str = Field(pattern="^\\d{8}$")

# Schema de Output de Benchmarks (API Result) Validado por Pydantic v2
class BenchmarkSeriesOutputSchema(BaseModel):
    model_config = ConfigDict(extra="forbid")

    benchmark: BenchmarkType
    base_currency: str = "BRL"
    points: List[QuotePointVO]
    count: int = Field(ge=0)

    @field_validator("count")
    @classmethod
    def validate_count_matches_points(cls, v: int, info) -> int:
        points = info.data.get("points", [])
        if v != len(points):
            return len(points)
        return v
